## 一、这三项不是新需求，是一笔旧账

2026-10-19 22:43:12，情绪取数移交后台线程；22:48:35 定时器再想发起时，发现锁还被占着，只能跳过。
中间隔了 **323 秒**，而同一策略的历史正常值是 **42 秒**（15:17:14 取数 → 15:17:56 信号刷新）。

323 秒这个数字不能只当"网络慢"。算一下就明白：

```
单批 300 只失败 → 拆 3 个 100 → 每个 100 再拆 4 个 30 = 单批最多 1 + 3×(1+4) = 16 次调用
18 批 × 16 次 × 2 轮（第二轮换全字段）= 最坏 576 次 get_market_data_ex
```

**接口越坏，重试越多。** V2.6.86 及以前是"一批失败就 continue"，几秒结束；
V2.6.87 加了拆批重试（本意是救回失败批次的票），但没加上限，于是把"快速失败"放大成了十分钟空转。

三项就是补这个洞。

## 二、改动明细

| # | 改动 | 位置 | 效果 |
|---|---|---|---|
| 1 | 取数总预算 180 秒 | `_sent_fetch_sync()` | 每批开始前检查，超预算带已取到部分收尾 |
| 2 | 接口整体不可用熔断 | `_sent_fetch_sync()` | 连续 3 批零成功 + 累计零成功 → 立即中止 |
| 3 | 跳过日志带已运行时长 | `sent_fetch_all_data()` | 区分"慢"与"卡死" |
| 附 | 零成功也写覆盖率明细 | `_sent_fetch_sync()` | 消除"失败 0 只 + 覆盖率 0%"的自相矛盾 |

### 1. 取数总预算

```python
_t_beg = time.time()
_BUDGET_SEC = 180.0
...
for _i in range(0, len(_stocks), 300):
    if time.time() - _t_beg >= _BUDGET_SEC:
        _budget_hit = True
        break
```

**为什么是 180 秒**：正常 42 秒，4 倍余量。开盘时段若真慢到 180 秒还没完，那批数据也不该用了
（行情接口出问题时的数据往往本身残缺）。超时后覆盖率自然不足 → 上游 `_sent_use_last_good()`
沿用上次成功信号，**不会用残缺数据算信号**。

**为什么不放模块级常量**：这条是硬约束。`_fp_keys()` 用 `globals()` 收集全部 `UPPER_CASE` 常量，
新增一个模块级常量就会改变参数指纹，让状态文件 `verified_fp` 的比对凭空失效 ——
为一个超时值付这个代价不值得。所以写成函数内局部常量（不进 `globals()`）。
实测：模块级大写常量 262 个，与 V2.6.89 **完全一致**，参数指纹仍 `8a4ab7e8`。

### 2. 整体不可用熔断

判据：**连续 3 批整批零成功 且 累计一只都没拿到**。

```
if _box[0] > _ok_before:   # 本批有成功 → 计数器归零
    _fail_streak = 0
else:
    _fail_streak += 1
...
if _fail_streak >= 3 and _box[0] == 0:
    _abort = True
    break
```

两个条件必须同时满足，是为了避免误杀：

- 只看"连续 3 批失败"→ 前 3 批恰好是冷门代码段时会误杀，而后面 15 批可能是好的；
- 加 `_box[0] == 0` → 只要中途任何一批成功过，就说明接口是活的，走正常的覆盖率判定，
  不提前放弃。

实测对比（假接口全抛异常，900 只 3 批）：

| | 调用次数 | 结果 |
|---|---|---|
| 旧版（无熔断） | 48 + 48（两轮全字段）= 96 | 跑满两轮才放弃 |
| 新版 | **48** | 3 批后立即中止，第二轮的"改用全字段重试"不再发生 |

按真实规模（5226 只 / 18 批）折算：旧版最坏 576 次，新版熔断在 **48 次**（3 批×16）截断，
约 **1/12**。

### 3. 跳过日志带已运行时长

改前：
```
[情绪] 情绪取数线程已在运行或锁不可用, 本轮跳过(中性, 不阻塞交易)
```
改后：
```
[情绪] 情绪取数线程已在运行(已运行323秒), 本轮跳过(中性, 不阻塞交易)
[情绪] 情绪取数线程已在运行(已运行400秒), 本轮跳过(中性, 不阻塞交易) —— 已超过取数总预算(180秒)的2倍, 疑似卡死; 情绪模块将全天中性, 建议重启策略(重启不影响持仓与状态文件)
```

顺带把一句话拆成两句：
- `_lock is None`（锁对象都创建失败，极罕见）→ `情绪取数锁不可用(无法并发保护)`
- 有线程持锁 → `情绪取数线程已在运行(已运行N秒)`

原来合并成"已在运行或锁不可用"，两种情况的处置完全不同（一个该等、一个只能重启），
却共用一句文案。

### 附. 顺手修掉的矛盾

旧版两轮都空时**不写** `_cov`，保留初始值 `fail=0`，于是日志会同时出现"失败 0 只"和"覆盖率 0%"
—— 看着像统计错了。现在零成功收尾（含熔断、超预算两条路径）也把失败/重试数写入。

4. 预算充足以为 3 次 → 实际 4 次（3 批 + 1 次指数）。

