## v1.2.65 = AUD27 手工仓分离 + 卖出铁律解耦（用户拍板）

用户原话：「手工买入的宁波银行股票，不占用策略持仓名额和投资金额。但是任何针对宁波银行
的卖出，都要检查亏损不卖和扣除税费之后赚钱的铁律，这个不要忘记了。」

**背景**：13:00:05 实盘用户手工买 1000 股 @34.83（成本 34830），v1.2.64 的
`_sync_state_to_actual` 把它整个当策略持仓接管——占了 3.48 万额度、tier 置 0、
`last_add_price=34.83`，机器准备按 M2 金字塔给它加仓。

**两本账设计（P1）**：策略账本 `position_shares/total_cost/deployed` 与手工账本
`manual_shares/manual_cost/manual_peak_cost/manual_sell_pending_until` 彻底分离。
外部持仓只写手工账本；`deployed` 只跟 `total_cost`；`tier` 空仓恒 -1（关键：否则下次
策略真开首仓会从第 2 档起步、少买 5 万）；`last_add_price` 不再回填券商均价。

**P2 卖出铁律解耦（本轮最关键的技术发现）**：手工仓移出策略账本后
`position_shares` 恒为 0，而原 R1 闸门条件是 `if position_shares > 0:` —— **整段跳过**，
等于给「亏损卖出」开后门。改为统一闸门 `_r1_net_profit_gate(code, actual_vol, broker_avg,
price, state, reason, sub_vol=None)`，一律以**券商实际持仓 + 实际成本**判：
- 成本价取 `max(券商均价, 策略账本均价, 手工账本均价)`，两本账并存按更保守的判
- 净到手 = 保守成交价×股数 − 佣金(max(mv×万0.841,5)) − 印花(万5) − 过户(万1)
- `净到手 <= 成本` 一律拒卖；异常 fail-closed
- 保守成交价与 `sell_all` 实际挂单价同口径（否则「按现价算赚、按挂单价成交倒亏」）

**P3 manual_sell**：只判卖不判买。三重条件（不写 tier/deployed；两本账并存让位策略
止盈链，避免一键全平账户；卖单在途冻结 + 跌停禁卖）。阈值=扣费后净赚≥4% 固定止盈
或移动止盈（激活 3% / 回落 2%）且仍净赚。`manual_takeover=True` 语义从「完全不碰」
升级为「只管卖、不管买」。

**踩坑**：`verify_position_before_order` 的第 4 个返回值是**原因文本**不是均价，
sell_all 里必须单独 `query_position_safe` 取 `_r1_avg`（3s 缓存，同根 bar 近零开销）。

**验收**：`_verify_final.py` 79→**116 项全通过**（新增 AUD27-P1a~P5d 共 38 项）；
`_test_manual_aud27.py` 46/46；`_regress_v1258.py` 通过；`_test_market_filter.py` 34/34；
`_test_dlinject.py` 12/12。交付件 v1.2.65 / 465,762 字节 / 8,655 行 / CRLF=0。

**`_verify_final.py` 三条旧断言必须随语义更新**（否则误报 FAIL）：
1. `P4 额度日志如实化` 原断言「未实现」→ AUD27 起改为「手工仓不计入占用，额度不再被吃」
2. `R1 净到手<=0 拦截` 原查 `_pnl_pct_s`（变量已不存在）→ 改查 `if _net <= _cost:`
3. `闸门不含止损语义` 不能直接搜函数全文——docstring 里就写着「不含任何止损语义」
   这句说明，必须先剔 docstring + 注释再搜实现体

## v1.2.66 = AUD28 修 v1.2.65 的实盘副作用（同日晚间，P0 级）

15:06 用户重启，v1.2.65 生效（版本自检 v1.2.65 / 构建 2026-10-20），但日志立刻暴露
一个 **明天开盘会真的重复买入** 的缺陷。

**缺陷 A（P0，根因）**：v1.2.65 把手工仓移出策略账本后 `position_shares` 恒 0，
而 handlebar 的外部同步触发条件是 `actual_vol != state["position_shares"]` ——
「券商1000 / 策略账本0」⇒ 恒不相等 ⇒ **每根 bar 都调一次 `_sync_state_to_actual`**。
函数尾部 `state["position_shares"] = actual_vol` 会把 1000 股**反复复活进策略账本**，
`verify_position_before_order` 里同一路径（`if not _sync_handled:` 分支）也会复活。
结果：两本账设计被完全推翻，日志表现为 init 后持续刷「【手工仓已分离】」。
修法：一致口径改为 `券商 == 策略+手工` 或 `券商 == 策略`，都不成立才同步；
verify 内补写时 `_strat28 = actual - manual_shares`（下限 0）。

**缺陷 B**：init「手工仓自检」打「手工持仓=0股」而券商实际 1000 股 —— 老状态文件
没有 `manual_*` 字段，迁移要等首根 bar。改为账本为空时以券商实际持仓+均价如实打印，
并标注`来源=券商实际(尚未迁移，首根bar落入手工账本)`。纯只读查询。

**缺陷 C**：全部标的被接管时 `_budget=0`，原打印「策略总预算 0 元」易被误读为策略停摆。
改为「策略侧买入预算 0 元 —— 本标的已人工接管…（这是预期状态，非故障）；卖出侧仍按铁律代卖」。

**验收**：新建 `_test_aud28.py`（**27 项**，含 5 组同步判定的行为级真值表）；
`_verify_final.py` 116/116；`_test_manual_aud27.py` 46/46；`_regress_v1258.py` 25 PASS；
`_test_market_filter.py` 34/34；`_test_dlinject.py` 12/12。
交付件 v1.2.66 / 469,689 字节 / 8,713 行 / CRLF=0 / md5 `0fe743c3...`。
备份 `.bak_20261020_v1265_pre_aud28`。

**教训**：改了「谁占额度」这类账本语义后，必须全局搜所有 `!= position_shares`
形式的差异判定点——两本账并存时它们全部失效，而且失效方式是**每根 bar 触发而非报错**，
只从日志「刷屏」才能看出来。
