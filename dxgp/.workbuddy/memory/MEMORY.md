## 4. 验证方法论
★ 断言被自身注释污染（已 6 次，元凶含 `stop_order`/`trap_credit_left`/`跳开`/`正常开仓`/`return data`）：负向断言新增文字不得含该标识符；版本说明一律中文转述；历史记录行保留原文 → 负向断言排除 docstring 只查代码区；全文子串断言太宽 → 按「行首缩进+整行」或 AST 节点判。
★ `'%' not in out` 会因 `%%` 假失败（已 4 次）→ 判据 `re.findall(r'%(?:\.\d+)?[sdf]', out)` 为空。
★ 期望值不许凭印象数/手算 → 用被测代码同一表达式算，格式串真渲染一次。
★ 干跑三原则：①副本与母版同步 ②真实 import+真实磁盘数据不注桩 ③覆盖输出段、守卫可达（窗口别开太小）。

★ 改行为必须全量扫同类文案（扫 AST Constant 排 docstring）；改了行为不改文案=日志骗人。
算费有副作用时同一笔成交不能算两次 → 算好的值当参数传（`fee=fee`）。
`ast.get_source_segment()` 保留 `\r\n`；`_check_inv.py` 的 `"".join(lines)` 把所有行粘成一行 → AST 校验必须用 `text` 原文。
