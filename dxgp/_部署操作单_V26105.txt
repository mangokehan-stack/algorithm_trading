第 4 步：重启策略让新代码生效
────────────────────────────────────────────────────────────

【结论】收盘后（15:00 之后）重启是安全的，推荐今天收盘后就做。

为什么不担心 QMT 回放历史 K 线？缩量低吸有三层天然防护
（已在母版中逐行核实，不是推测）：

  第①层  L11417  if G.use_run_time: return
          run_time 定时器注册成功后，handlebar 完全不干活，
          回放的历史 bar 全部空转。你的日志已确认：
          "策略状态驱动: run_time定时器(每30秒)"  ->  这一层已生效。

  第②层  L11420  if not ContextInfo.is_last_bar(): return
          万一 run_time 注册失败退回 handlebar 模式，
          回放的历史 bar 也过不去（只有最后一根实时 bar 才算）。

  第③层  L11572  if market_phase() == 'trading': run_round()
          所有买卖决策的唯一入口。market_phase() 取的是
          datetime.now() 系统真实钟点（L5360），不是 bar 的时间戳。
          所以 15:30 重启必然返回 off_hours，run_round() 根本不被调用。

三个窗口对比：

  窗口              回放下单风险   时间余量        推荐度
  ----------------- ------------ -------------- ------
  今天收盘后 15:00+   零（三层防护） 充裕+一晚可补救  ★最推荐
  明早 08:00~08:30    零（三层防护） 1小时，改错很赶  ○可行
  午休 11:30~13:00    零（三层防护） 仅30分钟，改错没退路  ×不推荐
  盘中任何时刻        有（真实交易时段）—              ×禁止

额外好处：收盘后重启不会重下数据
  step_day_init() 首行（L5388）判断 last_init_date == today 就直接 return，
  所以 【不会】重下 5226 只日线、【不会】重跑选股漏斗，
  只是重读状态文件 + 对账，几分钟就好。

其他注意：
  · 重启会清零 bh_streak 退避计数（影响很小，次日自然重置）
  · 宁波银行那边不要动 —— 它是另一个实例(交易端 - 2)、另一份代码

★ 唯一真实风险：不是回放误下单，是"改错了没时间改回来"。
  所以动手前务必先把编辑器里的原文整段复制到记事本备份
  （QMT 编辑器没有版本管理/撤销历史）。
