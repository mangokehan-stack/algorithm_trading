## 二、四项改动

### 改动 1：换手率闸门 100% 失效（真问题）

**哪里不对**

漏斗日志写着 `换手率不符0(字段缺失121)`。进入这一环的股票正好 121 只，**121 只全部取不到换手率**，于是 `ZT_TURNOVER_MIN = 0.05`、`ZT_TURNOVER_MAX = 0.20` 这两个参数从写进去那天起就一直是摆设。

根因：`load_history` 读的是 `turnover` / `turnover_ratio` 两列，但广发 QMT 的 `get_market_data_ex` 日线结果里**根本没有这两列**，取到的永远是 0。代码随后走到"缺失即放行"分支——设计本意是"宁可漏检不可误杀"，结果变成了"永远不检查"。

**举一个真实例子**

风语筑 603466，昨天日志选了它做第一优先：
- 基准量 1,468,009 手 = 1.468 亿股
- 流通市值约 60 亿 / 股价 13.57 → 流通股本约 4.42 亿股
- 换手率 ≈ 1.468 / 4.42 = **33.2%**

20% 上限的本意就是踢掉这种"高位巨量出货"形态，**它本该被剔除，却进了优先名单**。反过来，换手 1~2% 的一字板（买不到或者买到就套）该踢的也一个没踢。

**怎么改**

新增 `_float_share(stock)` 取流通股本（三种字段拼写 `CirculatingVolume` / `FloatVolume` / `FloatVolumn` 全试，与 `_float_market_cap_yi` 同口径，缓存 1 小时），字段缺失时自算：

```
换手率 = 成交量(手) × DAILY_VOL_UNIT ÷ 流通股本(股)
```

两路都拿不到才按"缺失放行"，绝不误杀。漏斗该行改为 `换手率不符N(自算X/缺失放行Y)`，一眼能看出走的是哪条路。

**风险（必须知道）**

闸门第一次真正生效，**候选会变少，某天可能 0 只**。这不是 bug，是恢复设计意图。阈值数值一个没动，所以参数指纹仍是 `8a4ab7e8`；但代码逻辑变了，版本指纹变为 `4c44540b`。

### 改动 2：心跳启动自证

**哪里不对**

V2.6.87 加了双实例检测，但日志里一个字都没有。这次核对我是**去 `bin.x64` 目录数 json 文件**才确认它在跑的——等于把可观测性外包给运维。更糟的是：如果心跳文件写失败（目录无权限），日志照样安静，你分不清"确实没有第二个实例"和"检测功能坏了"。

**怎么改**

`after_init` 强制首检时打一行：

```
[安全] 心跳已就绪: zt_shrink_heartbeat_8973786_18792.json (PID=18792, 双实例检测生效, 检测间隔30秒, 同伴心跳120秒内视为活跃)
```

写失败则打 `[安全][提示] 心跳文件写入失败(双实例检测将不可用)`。只在这一处打印，定时器轮次保持静默不刷屏。

**本次核对结果**：目录下只有 1 个心跳文件（PID 18792 / V2.6.87），22:42 之后为**单实例**。但 V2.6.87 是 22:42 才上线的，22:25 那次疑似双实例发生在旧版（无心跳），**无法回溯取证**。

### 改动 3：亏损筛选文案歧义

`按亏损筛选剔除12只` 与漏斗里的 `避雷风险12` 是**同一批**（亏损筛选并入 `st_risk` 计数），旧文案读起来像两批共 24 只。改为：

```
其中财务亏损剔除12只(归母净利润<0 12只, 数据缺失/查询异常 0只; 已计入上方漏斗"避雷风险", 不重复扣除)
```

### 改动 4：`基准量不足1` 加空格

`'基准量<=0 %d / 基准量不足%d'` → `'基准量<=0 %d / 基准量不足 %d'`。
